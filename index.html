Projects

RevenueProof

August 2026 · Solo project

Problem
An investor told a startup earned ₹1.5 crore has to open several systems to check it: contracts, invoices, payments, refunds and bank receipts. Doing that by hand for every rupee is slow and easy to get wrong.
Solution
RevenueProof pulls records from Zoho Books, Razorpay, HubSpot, Google Drive and bank CSVs, then rebuilds the evidence trail for each rupee. Money with a complete trail is proven. Money with a broken trail is reported with the missing link named. Reconciliation uses exact integer-paise arithmetic, disputed classifications go to a human reviewer, and a hash-chained audit log records every decision.
Stack
Python, FastAPI, Next.js, React, TypeScript, Tailwind CSS, PostgreSQL with row-level security, Neo4j, Redis, ChromaDB, OCR, OR-Tools.
My contribution
Sole author: the verification engine, deterministic money logic, per-workspace data isolation and audit trail.
Repository and documentation Live demo

TwinCouncil

August 2026 · Solo project

Problem
When a supplier delays a critical component, planners must decide quickly between recovery plans while inventory limits, costs and delivery estimates are all uncertain.
Solution
A multi-agent workflow decides whether a delay is a real risk, investigates uncertain evidence, and generates four deliberately different recovery plans. OR-Tools CP-SAT checks each plan is feasible. A Red-Team agent attacks each plan's assumptions, and a SimPy digital twin tests every plan against every attack. The most resilient plan is chosen by a deterministic score, and a human approves when policy requires it. Every step is written to a hash-linked audit ledger.
Stack
Python, FastAPI, WebSockets, Celery, React, TypeScript, PostgreSQL, Neo4j, Redis, Cerebras, OR-Tools, SimPy.
My contribution
Sole author: the agent workflow, the optimization and simulation pipeline, and the audit ledger. In a simulated incident the selected plan protected ₹44.3 lakh of production value.
Repository and documentation

PurposeBound Treasury

October 2026 · Hackathon team project (Track 2, Gemma)

Problem
NGOs, student bodies and sponsored events cannot easily show sponsors that money was spent for the purpose it was given for.
Solution
Gemma turns a funding agreement into enforceable spending rules. Each expense then passes four review agents (policy, evidence, budget, auditor) before a person approves it. Supporting documents stay in Google Drive, and only SHA-256 hashes are anchored. Payouts run through Razorpay sandbox Orders; vendor transfers were simulated in the demo.
Stack
Next.js, React, TypeScript, Tailwind CSS, Gemma, Google Drive API, Razorpay sandbox.
My contribution
Main developer: 18 of the repository's 19 commits, covering the rule builder, review agents and integrations.
Repository and documentation
